**Принцип:** для v0.1.0–v0.5.3 тег ставится на исторический коммит, в котором впервые появилась соответствующая версия. Последующие коммиты `chore(dev)` не передвигают релизный тег. Для **v0.5.4** тег должен указывать на атомарный `docs(sync)`-коммит, чтобы иконка, README и release notes присутствовали в скачиваемом исходном коде релиза. Сам исполняемый код 0.5.4 не менялся.

## Публикация с локального компьютера

Подключённый инструмент GitHub умеет коммитить исходники, но не предоставляет создание тегов и GitHub Release. Поэтому теги и релиз оформляются **локальным скриптом**, требующим Git и, для публикации, [GitHub CLI](https://cli.github.com/) (`gh auth login`).

В чистом клоне проекта выполни:

```powershell
git pull --ff-only origin main
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\release_history.ps1
```

Скрипт проверит SHA и `VERSION.json`, затем создаст все недостающие локальные **аннотированные** теги. Существующие совпадающие теги он пропустит; несовпадения завершат выполнение с ошибкой **без force**.

Чтобы опубликовать все исторические теги и **создать один GitHub Release v0.5.4 с текстом из `docs/releases/v0.5.4.md`**:

```powershell
gh auth login
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\release_history.ps1 -PushAll -PublishRelease
```

Для предварительной проверки добавь `-DryRun`. Для публикации **только текущего** тега и релиза (старые теги останутся локальными) используй `-PublishRelease` без `-PushAll`.

После успешной публикации страница релиза: [v0.5.4](https://github.com/TheColdVoid1337/vGUITAR/releases/tag/v0.5.4). Она появляется **только после фактического создания релиза через CLI**.
